DEVELOPER DOCS / ONE BASE URL

改一个地址，发出第一条请求。

兼容 OpenAI Chat Completions 与 Anthropic Messages 协议。先用最短示例跑通，再按业务需要选择模型和线路分组。

快速开始鉴权协议兼容线路分组错误处理
01 / QUICKSTART

快速开始

把 SDK 的 base_url 指向 SuperToken，使用控制台生成的 API Key，并传入模型 ID。

curl https://api.supertoken.cc/v1/chat/completions \ -H "x-api-key: sk-st-..." \ -H "Content-Type: application/json" \ -d '{ "model": "claude-opus-5", "messages": [{"role":"user","content":"你好"}], "stream": true }'
示例中的 Key 是占位符。真实 Key 只应保存在服务端环境变量中，不要写进前端代码或提交到仓库。
02 / AUTH

鉴权

官方文档推荐使用 x-api-key 请求头；兼容 OpenAI 的客户端也可以使用 Bearer Token。

x-api-key: $SUPERTOKEN_API_KEY Authorization: Bearer $SUPERTOKEN_API_KEY

不同环境建议创建独立 Key，便于隔离用量、吊销权限和核对账单。

03 / PROTOCOLS

协议兼容

同一个 Base URL 支持两类常用请求格式。选择与现有 SDK 一致的入口即可。

协议路径适用客户端
OpenAI Compatible/v1/chat/completionsOpenAI SDK、Cursor、NextChat 等
Anthropic Messages/v1/messagesAnthropic SDK、Claude Code 等
04 / ROUTE GROUPS

线路分组

需要指定线路时，在模型 ID 后增加 @分组名，或者传入请求头。没有指定时使用账户默认分组。

"model": "claude-opus-5@claude-max" X-Route-Group: claude-max

分组来源、倍率和实际输入/输出价格统一在定价页公开，最终扣费以控制台账单为准。

05 / ERRORS

错误处理

状态码含义建议处理
401Key 无效或已失效检查 Authorization 请求头
402账户余额不足核对余额与账单
429请求频率或上游限流指数退避后重试
5xx网关或上游异常记录 request_id 并查看状态页
